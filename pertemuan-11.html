01Tujuan & Prasyarat

Di akhir pertemuan ini, mahasiswa dapat menjelaskan kenapa accuracy bisa menyesatkan, menghitung dan membaca confusion matrix beserta precision/recall/F1, mengevaluasi klasifikasi biner dengan ROC-AUC, menerapkan k-fold cross-validation, serta membedakan overfitting dan underfitting untuk menuntun proses tuning hyperparameter.

  • Sudah familiar dengan alur train_test_split, fit, dan predict scikit-learn (Pertemuan 9-10).
  • Sudah pernah melatih minimal satu model klasifikasi (logistic regression, decision tree, atau KNN).
  • Library: numpy, pandas, matplotlib, scikit-learn sudah terpasang di environment datasci.

02Setup & Dataset Contoh

Sepanjang pertemuan ini kita memakai satu dataset konsisten: simulasi deteksi penyakit dari 4 fitur klinis (sudah dinormalisasi), dengan label 1 = sakit dan 0 = sehat. Kasus ini sengaja dibuat imbalanced — hanya sekitar 5% pasien yang benar-benar sakit, mirip kondisi nyata screening penyakit langka.

notebooks/11-evaluasi-model.ipynb
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression

X, y = make_classification(
    n_samples=1000, n_features=4, n_informative=3, n_redundant=0,
    weights=[0.95, 0.05], flip_y=0.01, random_state=42
)
df = pd.DataFrame(X, columns=["usia_z", "tekanan_darah_z", "kadar_gula_z", "bmi_z"])
df["sakit"] = y

print(df["sakit"].value_counts(normalize=True))

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.25, stratify=y, random_state=42
)

model = LogisticRegression()
model.fit(X_train, y_train)
y_pred = model.predict(X_test)
Kenapa stratify=y?

Pada dataset imbalanced, stratify=y memastikan proporsi kelas 0/1 di train dan test tetap sama dengan proporsi di data asli — tanpa ini, bisa saja test set kebetulan tidak memuat satu pun kasus positif.

03Kenapa Accuracy Saja Tidak Cukup

Accuracy mengukur proporsi prediksi yang benar dari seluruh data. Terlihat masuk akal, tapi pada data imbalanced seperti dataset kita (95% sehat, 5% sakit), model yang selalu menebak "sehat" tanpa belajar apa pun sudah mendapat accuracy tinggi.

python
from sklearn.dummy import DummyClassifier
from sklearn.metrics import accuracy_score

dummy = DummyClassifier(strategy="most_frequent")
dummy.fit(X_train, y_train)
y_pred_dummy = dummy.predict(X_test)

print("Accuracy model 'malas':", accuracy_score(y_test, y_pred_dummy))
# Accuracy model 'malas': 0.952 (!!)
Model yang tidak berguna, tapi accuracy 95%

DummyClassifier di atas tidak pernah mendeteksi satu pun pasien sakit — padahal itulah tujuan utama model ini dibuat. Accuracy 95% menyembunyikan kegagalan total pada kelas minoritas, yang justru paling penting.

Karena itu, untuk data imbalanced (dan klasifikasi pada umumnya), kita butuh metrik yang melihat performa per kelas, bukan hanya rata-rata keseluruhan.

04Confusion Matrix: TP, TN, FP, FN

Confusion matrix membandingkan label aktual dengan label prediksi dalam 4 kategori, untuk klasifikasi biner (anggap "sakit" sebagai kelas positif):

IstilahArtiContoh pada kasus deteksi penyakit
TP (True Positive)Diprediksi positif, aktual positifPasien sakit, model benar bilang sakit
TN (True Negative)Diprediksi negatif, aktual negatifPasien sehat, model benar bilang sehat
FP (False Positive)Diprediksi positif, aktual negatifPasien sehat, model salah bilang sakit ("false alarm")
FN (False Negative)Diprediksi negatif, aktual positifPasien sakit, model salah bilang sehat ("terlewat")
FN sering paling berbahaya

Pada kasus medis, False Negative (pasien sakit dianggap sehat) biasanya jauh lebih berisiko daripada False Positive, karena penyakitnya tidak tertangani. Ini jadi alasan kenapa metrik seperti recall penting di bagian 08.

05Confusion Matrix dengan scikit-learn

python
from sklearn.metrics import confusion_matrix, ConfusionMatrixDisplay

cm = confusion_matrix(y_test, y_pred)
print(cm)
# [[233   4]
#  [  6   7]]

disp = ConfusionMatrixDisplay(confusion_matrix=cm, display_labels=["Sehat", "Sakit"])
disp.plot(cmap="Blues")
plt.title("Confusion Matrix - Deteksi Penyakit")
plt.show()

Susunan baris adalah label aktual, kolom adalah label prediksi. Baris pertama (aktual sehat) dan kolom pertama (prediksi sehat) berpotongan di posisi TN; baris kedua kolom kedua berpotongan di posisi TP.

Tanda berhasil

cm.ravel() dapat dipecah menjadi tn, fp, fn, tp = cm.ravel() dan jumlah keempatnya sama dengan total baris di y_test.

06Precision, Recall, F1-Score

Dari confusion matrix, tiga metrik turunan paling penting untuk kelas positif:

  • Precision = TP / (TP + FP) — dari semua yang diprediksi positif, berapa persen yang benar-benar positif. Tinggi berarti sedikit false alarm.
  • Recall (sensitivity) = TP / (TP + FN) — dari semua yang aktual positif, berapa persen yang berhasil ditangkap model. Tinggi berarti sedikit kasus positif yang terlewat.
  • F1-score = 2 × (precision × recall) / (precision + recall) — rata-rata harmonik precision dan recall, berguna saat ingin menyeimbangkan keduanya dalam satu angka.
python
tn, fp, fn, tp = cm.ravel()

precision = tp / (tp + fp)
recall = tp / (tp + fn)
f1 = 2 * (precision * recall) / (precision + recall)

print(f"Precision: {precision:.2f}")
print(f"Recall:    {recall:.2f}")
print(f"F1-score:  {f1:.2f}")

07classification_report

Daripada menghitung manual, scikit-learn menyediakan classification_report yang langsung merangkum precision, recall, F1-score, dan support (jumlah sampel) untuk tiap kelas.

python
from sklearn.metrics import classification_report

print(classification_report(y_test, y_pred, target_names=["Sehat", "Sakit"]))
#               precision    recall  f1-score   support
#
#        Sehat       0.97      0.98      0.98       237
#        Sakit       0.64      0.54      0.58        13
#
#     accuracy                           0.96       250
#    macro avg       0.80      0.76      0.78       250
# weighted avg       0.96      0.96      0.96       250

Perhatikan betapa berbedanya performa kelas Sakit (recall 0.54) dibanding accuracy keseluruhan (0.96) — ini bukti nyata kenapa membaca classification_report per kelas jauh lebih informatif.

08Kapan Precision, Kapan Recall

Metrik mana yang "lebih penting" tergantung konteks bisnis — mana yang lebih mahal: false positive atau false negative?

KasusMetrik prioritasAlasan
Deteksi penyakit seriusRecallLebih baik banyak false alarm (pasien sehat disuruh cek ulang) daripada melewatkan pasien yang benar sakit (FN berbahaya).
Deteksi email spamPrecisionEmail penting yang salah ditandai spam (FP) merugikan pengguna; lebih bisa ditoleransi jika sedikit spam lolos (FN).
Rekomendasi produkF1 / seimbangBaik FP (rekomendasi tidak relevan) maupun FN (produk relevan tidak muncul) sama-sama merugikan pengalaman pengguna.
Aturan praktis

Tanyakan: "apa akibat jika model salah memprediksi positif?" dan "apa akibat jika model salah memprediksi negatif?" Metrik yang mengukur akibat paling mahal itulah yang harus diprioritaskan saat memilih model atau threshold.

09ROC Curve & AUC

ROC curve (Receiver Operating Characteristic) memplot True Positive Rate (recall) terhadap False Positive Rate pada berbagai ambang batas (threshold) klasifikasi, bukan hanya threshold default 0.5. AUC (Area Under Curve) merangkum kurva ini menjadi satu angka 0-1: 0.5 berarti model menebak acak, 1.0 berarti model sempurna memisahkan kedua kelas.

python
from sklearn.metrics import roc_auc_score, roc_curve

y_proba = model.predict_proba(X_test)[:, 1]
auc = roc_auc_score(y_test, y_proba)
fpr, tpr, thresholds = roc_curve(y_test, y_proba)

print("AUC:", round(auc, 3))

plt.plot(fpr, tpr, label=f"Logistic Regression (AUC = {auc:.2f})")
plt.plot([0, 1], [0, 1], linestyle="--", color="gray", label="Tebakan acak")
plt.xlabel("False Positive Rate")
plt.ylabel("True Positive Rate")
plt.title("ROC Curve - Deteksi Penyakit")
plt.legend()
plt.show()
Kenapa pakai predict_proba, bukan predict?

ROC-AUC butuh skor probabilitas (seberapa yakin model), bukan label final 0/1, karena kurva dibangun dengan menggeser threshold keputusan dari 0 sampai 1.

10Cross-Validation K-Fold

Satu kali train_test_split bisa "beruntung" atau "sial" tergantung pembagian data. K-Fold Cross-Validation membagi data menjadi k bagian (fold), melatih model k kali — tiap kali dengan 1 fold berbeda sebagai test set dan sisanya sebagai train set — lalu merata-ratakan hasilnya.

python
from sklearn.model_selection import cross_val_score, KFold

kf = KFold(n_splits=5, shuffle=True, random_state=42)
scores = cross_val_score(LogisticRegression(), X, y, cv=kf, scoring="f1")

print("F1 tiap fold:", np.round(scores, 3))
print("Rata-rata F1:", round(scores.mean(), 3))
print("Standar deviasi:", round(scores.std(), 3))
Tanda hasil masuk akal

Lima skor F1 pada scores relatif dekat satu sama lain (standar deviasi kecil) menandakan performa model stabil di berbagai pembagian data, bukan kebetulan dari satu split tertentu.

11Kenapa Cross-Validation Lebih Reliable

  • Mengurangi varians estimasi performa — rata-rata dari 5-10 percobaan jauh lebih stabil daripada satu angka dari satu split.
  • Semua data pernah jadi test set — tiap baris data dipakai untuk validasi tepat sekali, sehingga tidak ada "data beruntung" yang kebetulan mudah diprediksi.
  • Mendeteksi model yang tidak stabil — jika skor antar fold sangat bervariasi, itu pertanda model sensitif terhadap pembagian data (mungkin data terlalu sedikit atau model terlalu kompleks).
Cross-validation bukan pengganti test set akhir

Cross-validation umumnya dipakai saat eksperimen & tuning (bagian 14). Tetap sisihkan satu held-out test set yang baru disentuh di akhir, untuk evaluasi final yang benar-benar independen dari proses tuning.

12Overfitting vs Underfitting

Underfitting terjadi saat model terlalu sederhana untuk menangkap pola data — error tinggi baik di train maupun test. Overfitting terjadi saat model terlalu kompleks, menghafal noise di data train — error rendah di train tapi tinggi di test. Ilustrasi berikut memvariasikan kompleksitas DecisionTreeClassifier lewat max_depth:

python
from sklearn.tree import DecisionTreeClassifier
from sklearn.metrics import accuracy_score

depths = range(1, 15)
train_scores, test_scores = [], []

for d in depths:
    tree = DecisionTreeClassifier(max_depth=d, random_state=42)
    tree.fit(X_train, y_train)
    train_scores.append(accuracy_score(y_train, tree.predict(X_train)))
    test_scores.append(accuracy_score(y_test, tree.predict(X_test)))

plt.plot(depths, train_scores, marker="o", label="Akurasi Train")
plt.plot(depths, test_scores, marker="o", label="Akurasi Test")
plt.xlabel("max_depth (kompleksitas model)")
plt.ylabel("Akurasi")
plt.title("Overfitting vs Underfitting")
plt.legend()
plt.show()

Pola yang biasanya muncul: di max_depth kecil, kedua kurva sama-sama rendah (underfitting). Seiring max_depth membesar, akurasi train terus naik mendekati 1.0, sementara akurasi test mulai stagnan lalu menurun — titik di mana kurva test mulai turun itulah awal overfitting.

13Bias-Variance Tradeoff

Secara konseptual, error model bisa dipecah menjadi tiga sumber: bias (kesalahan karena model terlalu sederhana/asumsi terlalu kaku), variance (kesalahan karena model terlalu sensitif terhadap fluktuasi data latih), dan noise (ketidakpastian bawaan data yang tidak bisa dihilangkan model apa pun).

KondisiBiasVarianceGejala
UnderfittingTinggiRendahError train & test sama-sama tinggi
Pas (good fit)SedangSedangError train & test rendah dan berdekatan
OverfittingRendahTinggiError train sangat rendah, error test jauh lebih tinggi
Kenapa disebut "tradeoff"?

Menurunkan bias (menambah kompleksitas model) biasanya menaikkan variance, dan sebaliknya. Tujuan tuning model bukan menghilangkan keduanya, tapi mencari titik keseimbangan yang meminimalkan total error pada data baru.

14Hyperparameter Tuning: GridSearchCV

Daripada mencoba kombinasi hyperparameter satu-satu secara manual, GridSearchCV mencoba semua kombinasi pada grid yang ditentukan, mengevaluasi tiap kombinasi dengan cross-validation, lalu memilih kombinasi dengan skor terbaik.

python
from sklearn.model_selection import GridSearchCV
from sklearn.ensemble import RandomForestClassifier

param_grid = {
    "n_estimators": [50, 100, 200],
    "max_depth": [3, 5, 10, None],
}

grid = GridSearchCV(
    RandomForestClassifier(random_state=42, class_weight="balanced"),
    param_grid,
    cv=5,
    scoring="f1",
    n_jobs=-1,
)
grid.fit(X_train, y_train)

print("Parameter terbaik:", grid.best_params_)
print("F1 terbaik (rata-rata CV):", round(grid.best_score_, 3))

best_model = grid.best_estimator_
print(classification_report(y_test, best_model.predict(X_test), target_names=["Sehat", "Sakit"]))
Tanda proses berjalan benar

grid.best_params_ mengembalikan satu kombinasi parameter spesifik dari param_grid, dan grid.best_score_ adalah rata-rata skor cross-validation untuk kombinasi tersebut — bukan skor dari test set.

GridSearchCV lambat untuk grid besar

Jumlah kombinasi tumbuh cepat (3 × 4 = 12 kombinasi × 5 fold = 60 pelatihan model). Untuk grid yang sangat besar, pertimbangkan RandomizedSearchCV yang mencoba sampel kombinasi acak, bukan semuanya.
