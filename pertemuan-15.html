Deploy Model: FastAPI & Streamlit

Model yang hanya bisa dijalankan di notebook pribadi belum benar-benar berguna. Pertemuan ini membawa pipeline terlatih dari Pertemuan 13 keluar dari notebook: menjadi REST API dengan FastAPI, atau dashboard interaktif dengan Streamlit.

01Tujuan & Prasyarat

Di akhir pertemuan ini, mahasiswa dapat menyimpan pipeline scikit-learn terlatih dan menyajikannya sebagai layanan yang bisa diakses pihak lain — baik melalui REST API (FastAPI) maupun dashboard interaktif (Streamlit).

  • Sudah memiliki pipeline terlatih dari Pertemuan 13 (scikit-learn Pipeline dengan preprocessing + model), atau model sederhana dari Pertemuan 9-10.
  • Environment Python aktif dengan scikit-learn dan joblib sudah terpasang.
  • Familiar dengan konsep dasar HTTP (request, response, JSON) — tidak wajib expert, cukup paham konsepnya.

02Kenapa Model Bagus di Notebook Belum Tentu Berguna

Sebuah model dengan akurasi tinggi di model.ipynb hanya berguna bagi orang yang membuka notebook itu. Rekan kerja, aplikasi mobile, atau sistem lain tidak bisa "membuka notebook" untuk mendapatkan prediksi — mereka butuh cara mengakses model tanpa harus menjalankan Python dan memahami kode di baliknya.

Deploy adalah proses membungkus model menjadi layanan yang bisa dipanggil dari luar: lewat alamat web (API) yang mengembalikan JSON, atau lewat antarmuka visual (dashboard) yang bisa diklik orang awam. Tanpa tahap ini, siklus OSEMN terasa berhenti di "Model" — padahal nilai sebenarnya baru terasa saat model dipakai orang lain untuk mengambil keputusan.

Analogi sederhana

Notebook adalah dapur tempat resep (model) diuji coba. Deploy adalah membuka restoran — orang lain memesan makanan (meminta prediksi) tanpa perlu tahu cara memasaknya.

03Menyimpan Pipeline Terlatih dengan joblib

Di Pertemuan 13, pipeline (preprocessing + model) sudah dilatih dan disimpan. Berikut ringkasan singkat cara menyimpan & memuatnya kembali, sebagai titik awal pertemuan ini:

latih_dan_simpan.py
import joblib
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline([
    ("scaler", StandardScaler()),
    ("model", LogisticRegression())
])
pipeline.fit(X_train, y_train)

joblib.dump(pipeline, "model_pipeline.joblib")
print("Pipeline tersimpan di model_pipeline.joblib")

File model_pipeline.joblib inilah yang akan dimuat ulang oleh API atau dashboard — tanpa perlu melatih ulang model setiap kali aplikasi dijalankan.

Tanda berhasil

File model_pipeline.joblib muncul di folder proyek, dan joblib.load("model_pipeline.joblib") mengembalikan objek pipeline yang bisa langsung dipanggil .predict().

04Mengenal FastAPI

FastAPI adalah framework Python untuk membangun REST API secara cepat, dengan validasi data otomatis dan dokumentasi interaktif yang ter-generate sendiri. FastAPI cocok dipakai saat prediksi model perlu diakses oleh aplikasi lain (mobile app, web app, sistem lain) dalam format terstruktur (JSON).

Struktur dasar proyek deploy dengan FastAPI:

struktur folder
deploy-model/
├── model_pipeline.joblib    hasil joblib.dump dari Pertemuan 13
├── main.py                  kode FastAPI
└── requirements.txt

05Instalasi FastAPI & uvicorn

uvicorn adalah server ASGI yang menjalankan aplikasi FastAPI. Keduanya perlu dipasang di environment yang sama dengan model:

terminal
pip install fastapi uvicorn

# simpan ke requirements.txt
pip freeze > requirements.txt

06Membangun Endpoint POST /predict

Endpoint adalah "pintu masuk" API. Kita membuat satu endpoint POST /predict yang menerima data fitur dalam format JSON, lalu mengembalikan hasil prediksi:

main.py
from fastapi import FastAPI
from pydantic import BaseModel
import joblib
import numpy as np

app = FastAPI(title="API Prediksi Model")
pipeline = joblib.load("model_pipeline.joblib")

class InputData(BaseModel):
    fitur_1: float
    fitur_2: float
    fitur_3: float

@app.post("/predict")
def predict(data: InputData):
    X = np.array([[data.fitur_1, data.fitur_2, data.fitur_3]])
    hasil = pipeline.predict(X)[0]
    return {"prediksi": str(hasil)}

Model dimuat satu kali saat aplikasi start (di luar fungsi predict), bukan setiap kali ada request masuk — ini membuat API jauh lebih cepat merespons.

07Menjalankan Server dengan uvicorn

terminal
uvicorn main:app --reload

main:app berarti "muat objek app dari file main.py". Flag --reload membuat server otomatis me-restart saat kode diubah — berguna selama pengembangan, biasanya dimatikan saat benar-benar production.

Tanda berhasil

Terminal menampilkan Uvicorn running on http://127.0.0.1:8000 tanpa pesan error di bawahnya.

08Menguji API: curl & Dokumentasi Otomatis /docs

FastAPI otomatis menghasilkan dokumentasi interaktif (Swagger UI) di /docs — buka http://127.0.0.1:8000/docs di browser untuk mencoba endpoint langsung dari antarmuka web tanpa menulis kode apa pun.

Atau uji lewat terminal dengan curl:

terminal
curl -X POST "http://127.0.0.1:8000/predict" \
  -H "Content-Type: application/json" \
  -d '{"fitur_1": 5.2, "fitur_2": 3.1, "fitur_3": 1.4}'

# {"prediksi":"1"}
Error Connection refused

Server uvicorn belum berjalan, atau dijalankan di terminal/tab yang berbeda dari tempat curl dijalankan. Pastikan server masih aktif di terminal lain sebelum mengirim request.

09Validasi Input dengan Pydantic

Class InputData(BaseModel) pada bagian 06 bukan sekadar anotasi tipe — FastAPI memakainya untuk memvalidasi otomatis data yang masuk. Jika klien mengirim fitur_1 berupa teks yang tidak bisa diubah ke angka, FastAPI langsung menolak request dengan pesan error yang jelas, sebelum kode predict() sempat dijalankan.

contoh respons error otomatis
{
  "detail": [
    {"loc": ["body", "fitur_1"], "msg": "value is not a valid float", "type": "type_error.float"}
  ]
}
Kenapa ini penting

Validasi di lapisan API mencegah data kotor/salah format sampai ke model, yang bisa menyebabkan error sulit ditelusuri atau — lebih buruk — prediksi yang salah tanpa pemberitahuan.

10Mengenal Streamlit

Streamlit adalah framework Python untuk membangun dashboard/aplikasi web interaktif tanpa perlu menulis HTML, CSS, atau JavaScript. Cocok dipakai saat hasil prediksi perlu langsung dilihat dan dioperasikan manusia lewat form, tombol, dan tampilan visual — bukan dikonsumsi sistem lain.

terminal
pip install streamlit

11Membangun Dashboard Interaktif dengan Streamlit

Dashboard sederhana berikut memuat pipeline yang sama, menampilkan form input, dan tombol untuk memicu prediksi:

app.py
import streamlit as st
import joblib
import numpy as np

pipeline = joblib.load("model_pipeline.joblib")

st.title("Dashboard Prediksi Model")
st.write("Masukkan nilai fitur untuk melihat hasil prediksi.")

fitur_1 = st.number_input("Fitur 1", value=0.0)
fitur_2 = st.number_input("Fitur 2", value=0.0)
fitur_3 = st.selectbox("Fitur 3 (kategori)", options=[0, 1, 2])

if st.button("Prediksi"):
    X = np.array([[fitur_1, fitur_2, fitur_3]])
    hasil = pipeline.predict(X)[0]
    st.success(f"Hasil prediksi: {hasil}")

st.number_input dan st.selectbox membuat form input, sedangkan st.button menunda eksekusi kode prediksi sampai pengguna benar-benar mengklik tombol — bukan setiap kali halaman dimuat ulang.

12Menjalankan Dashboard

terminal
streamlit run app.py

Perintah ini otomatis membuka browser ke http://localhost:8501 dengan dashboard yang sudah bisa langsung dipakai.

Tanda berhasil

Form input, tombol "Prediksi", dan hasil st.success(...) muncul di browser tanpa pesan ModuleNotFoundError atau FileNotFoundError (pastikan model_pipeline.joblib ada di folder yang sama dengan app.py).

13FastAPI vs Streamlit: Kapan Pakai yang Mana

KriteriaFastAPIStreamlit
Konsumen utamaAplikasi/sistem lain (mobile, web, service lain)Manusia langsung lewat browser
Format outputJSON terstrukturTampilan visual (teks, grafik, tabel)
Butuh tampilan UI?Tidak — hanya endpointYa — form & komponen visual bawaan
Cocok untukIntegrasi ke aplikasi produksiDemo, prototipe, dashboard internal

Keduanya tidak saling eksklusif — proyek yang lebih matang sering memakai FastAPI sebagai "otak" (endpoint prediksi) dan Streamlit sebagai "wajah" yang memanggil endpoint tersebut.

14Checklist Sebelum Deploy

  • Model sudah divalidasi — metrik evaluasi (Pertemuan 11) sudah diperiksa dan dianggap layak, bukan model pertama yang kebetulan jalan.
  • Input tervalidasi — tipe data dan rentang nilai yang masuk akal sudah dicek (lewat Pydantic di FastAPI, atau pengecekan manual di Streamlit).
  • Error handling untuk input tidak valid — aplikasi tidak crash total saat menerima input aneh, melainkan mengembalikan pesan error yang jelas.
  • Dependency tercatat — requirements.txt lengkap dan versi library konsisten dengan yang dipakai saat melatih model.
Jangan lupa

Model yang dilatih dengan versi scikit-learn tertentu kadang tidak kompatibel saat dimuat dengan versi yang berbeda. Catat versi scikit-learn yang dipakai saat joblib.dump ke dalam requirements.txt.

Tidak wajib online

Untuk kebutuhan tugas kuliah, menjalankan API/dashboard secara lokal dan mendemokannya lewat screen recording atau presentasi langsung sudah cukup — deploy online adalah nilai tambah, bukan keharusan (lihat juga ketentuan UAS di Pertemuan 16).

16Latihan

  1. Ambil salah satu model (regresi dari Pertemuan 9 atau klasifikasi dari Pertemuan 10) yang sudah dilatih, simpan pipeline-nya dengan joblib.dump.
  2. Bangun endpoint POST /predict dengan FastAPI yang menerima fitur sesuai model tersebut, lalu uji lewat /docs dan curl.
  3. Sebagai alternatif/pelengkap, bangun juga dashboard Streamlit sederhana untuk model yang sama, dengan minimal dua jenis input (st.number_input dan st.selectbox).
  4. Tulis checklist dari bagian 14 dan centang satu per satu untuk proyekmu sendiri sebelum dianggap "siap demo".
